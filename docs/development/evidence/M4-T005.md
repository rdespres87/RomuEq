# M4-T005 — Real-Time Safety Gate

**Status:** ✅ PASS

## Gate Requirements

### REQ-RT-001: Allocation-Free Hot Path

**Criterion:** `process()`, `process_dsp()`, and `push_automation_event()` perform zero heap allocations.

**Evidence:**

- `EngineLifecycle::new()` — all arrays are inline in the struct:
  - `buffer: [f32; FLAT_BUFFER_SIZE]` (inline, no heap)
  - `delay_line: [f32; DELAY_BUFFER_SIZE]` (inline, no heap)
  - `bypass_buffer: [f32; FLAT_BUFFER_SIZE]` (inline, no heap)
- `prepare()` — only zeroes buffers, no allocation
- `process()` — copy_from_slice into flat buffer, calls `process_dsp()`, copy_to_slice from flat buffer. No `Vec::new`, `.push()`, `Box::new`, `Arc::new`, or `.resize()`
- `process_dsp()` — iterates bands/channels over pre-allocated delay lines. All state is stack-local (`x1`, `x2`, `y1`, `y2`) or from the flat delay-line array.
- `push_automation_event()` — calls `ingestor.push_event(event)` which stores into the pre-allocated `AutomationStream`. No allocation.
- `set_parameters()` — copies `EqParameters` (Copy trait), no allocation.

**Static analysis:** grep for `Vec::new`, `.push(`, `Box::new`, `Arc::new`, `.resize(`, `.clear(` in the hot path methods returns zero matches.

### REQ-RT-002: Non-Blocking Hot Path

**Criterion:** No blocking syscalls, no mutex contention, no channel receive in the audio thread path.

**Evidence:**

- `EngineHost::send_parameter_command()` (plugin.rs:66) uses `try_send()` — non-blocking. If channel is full, command is dropped (best-effort).
- `AutomationIngestor` has no blocking primitives — events are buffered in `AutomationStream` and processed synchronously.
- No `.recv()`, no `.lock()` calls in `process()` or `process_dsp()`.
- No I/O syscalls (no file reads, no network).

### REQ-AUTO-001: Host Event Offsets

**Criterion:** Automation events are validated against block length, ordered by `(sample_offset, sequence)`, and deduplicated.

**Evidence:**

- `AutomationIngestor::process_block(block_length)` calls `finalize_block(block_length)` which validates all events.
- Events with `sample_offset >= block_length` are silently dropped (automation.rs:61).
- `AutomationStream::finalize_block()` in romueq-common validates offsets.
- Events are sorted by `(sample_offset, sequence)` for deterministic ordering.
- Deduplication: events targeting the same parameter at the same offset keep the highest sequence number.

### REQ-BYPASS-001: Bypass Behavior

**Criterion:** Click-free bypass transition using 10ms equal-power crossfade.

**Evidence:**

- State tracking: `prev_bypass` and `curr_bypass` detect state changes.
- Transition detection: `if self.curr_bypass != bypass` triggers crossfade (lifecycle.rs:392).
- `bypass_buffer: [f32; FLAT_BUFFER_SIZE]` stores the input signal for crossfade blending.
- `crossfade_samples` = 441 samples (10ms @ 44100 Hz).
- Equal-power curve: `cos²(t * π/2)` applied per sample during transition.
- `transitioning` flag gates the crossfade blending logic.
- Bypass reset on `prepare()` clears all transition state.

**Test coverage:** M4-T004 commit includes tests for:
- Crossfade duration (441 samples = 10ms @ 44100 Hz)
- Equal-power curve correctness
- Struct size verification (525568 bytes — flat buffer fits)

### REQ-DET-001: Deterministic Processing

**Criterion:** Processing is deterministic — same inputs always produce same outputs.

**Evidence:**

- No `HashMap` iteration in hot path (HashMap has non-deterministic order).
- Automation events sorted by `(sample_offset, sequence)` — deterministic ordering.
- `sample_offset` monotonically increases by `block_size` each block.
- `blocks_processed` counter tracks blocks processed.
- No random number generation in DSP path.
- All biquad filter computations are pure functions of input samples and delay state.
- Automation interpolation is deterministic: linear/hold modes produce identical results for identical inputs.
